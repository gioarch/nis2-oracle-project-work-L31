# Esecuzione del progetto su Oracle

## Requisiti

Gli script utilizzano sintassi Oracle. Le colonne `GENERATED BY DEFAULT AS IDENTITY` richiedono Oracle Database 12c o una versione successiva.

Per lo script di esportazione CSV è richiesto Oracle SQLcl. Gli altri script possono essere eseguiti anche con Oracle SQL Developer.

Il collaudo degli script è in corso. Schema, indici, dataset, VIEW e query sono stati eseguiti su Oracle Database 26ai; restano da completare i test finali e l'esportazione CSV.

## Preparazione

Prima dell'esecuzione è consigliabile utilizzare uno schema utente dedicato e privo degli oggetti del progetto.

L'utente deve poter creare tabelle, indici e VIEW. I file devono essere eseguiti in una sessione configurata correttamente per i caratteri utilizzati dal progetto.

Le credenziali di accesso non devono essere inserite negli script o salvate nel repository.

Un esempio di avvio di SQLcl è:

```text
sql <utente>@<servizio_oracle>
```

La password può essere fornita in modo interattivo al momento della connessione.

### Query multilinea con SQLcl

Durante il collaudo è stato rilevato che, con `SQLBLANKLINES` disattivato, le righe vuote presenti nelle query con `UNION ALL` possono interrompere prematuramente l'istruzione.

Per questo motivo `sql/05_queries.sql` abilita esplicitamente:

```sql
SET SQLBLANKLINES ON
```

In questo modo le query multilinea vengono interpretate correttamente anche quando contengono righe vuote.

## Ordine degli script

Dalla directory principale del repository eseguire:

```text
@sql/01_schema.sql
@sql/02_indexes.sql
@sql/03_dataset.sql
@sql/04_views.sql
@sql/05_queries.sql
@sql/06_tests.sql
@sql/07_export_sqlcl.sql
```

L'ordine è importante perché gli script successivi utilizzano gli oggetti e i dati creati da quelli precedenti.

Lo schema viene creato per primo, seguito dagli indici e dal dataset. La VIEW viene creata prima dei test e dell'esportazione.

## In caso di errore

Gli errori Oracle `ORA-` durante la creazione degli oggetti o il caricamento dei dati devono essere controllati prima di continuare.

Se l'esecuzione si interrompe a metà, è preferibile verificare lo stato dello schema prima di rilanciare gli script. Gli script del progetto non contengono comandi `DROP` e non eliminano automaticamente gli oggetti già presenti.

Per una nuova prova è quindi preferibile utilizzare uno schema vuoto oppure rimuovere in modo controllato gli oggetti della precedente esecuzione.

## Controlli sugli oggetti

Dopo l'esecuzione possono essere utilizzate le viste del dizionario Oracle accessibili all'utente.

Esempi:

```sql
SELECT table_name
FROM user_tables
ORDER BY table_name;

SELECT view_name
FROM user_views
WHERE view_name = 'VW_EXPORT_NIS2_DEMO';

SELECT constraint_name, constraint_type, status
FROM user_constraints
ORDER BY table_name, constraint_name;

SELECT index_name, table_name
FROM user_indexes
ORDER BY table_name, index_name;
```

I controlli principali sono:

- presenza delle 13 tabelle;
- presenza della VIEW `VW_EXPORT_NIS2_DEMO`;
- caricamento completo del dataset;
- esito `OK` dei controlli contenuti in `06_tests.sql`;
- generazione del file CSV da parte di `07_export_sqlcl.sql`.

## Log dell'esecuzione

Durante il collaudo SQLcl può essere utilizzato anche per salvare l'output della sessione:

```text
SPOOL evidenza_esecuzione.log
-- esecuzione degli script
SPOOL OFF
```

I log utilizzati come evidenza devono provenire dall'esecuzione reale. Prima di pubblicarli va verificato che non contengano password, token o altri dati di connessione da non condividere.
